# QR612

**https://qr612.chichiboo.link**

URL을 입력하면 그 URL을 인코딩한 QR코드를 **8가지 테마의 3D 씬**으로 보여주는 웹앱입니다.

- **보기** — 아이소메트릭 3D 씬. 드래그로 시점을 돌립니다.
- **스캔** — 탭하면 탑다운 뷰로 전환되며 실제로 스캔 가능한 QR코드가 됩니다.
- **QR 여행** — 1인칭으로 QR 안에 걸어 들어갑니다. dark 모듈은 벽, light 모듈은 길입니다.
  걷고 뛰고 점프해서 블록 위에 올라가고, 곳곳에 숨은 지점을 찾습니다.

모든 처리는 브라우저 안에서 끝나며, 입력한 URL은 어떤 서버로도 전송되지 않습니다.

### 테마 표현 개선 (2026년 8월)

- **도시의 밤:** 순환도로 폭을 넓혀 중앙선으로 나뉜 2차선으로 만들었습니다. 안쪽
  차선은 시계 방향, 바깥 차선은 반시계 방향으로 고정했으며 자동차의 로컬 앞축을
  실제 진행 접선에 맞춰 옆으로 미끄러지거나 같은 차선에서 충돌하지 않습니다.
- **스캔 결과:** 최종 카드가 dark 모듈만 칠하던 방식을 바꿔 light 모듈까지 3D 장면과
  같은 계열의 셀별 팔레트로 렌더링합니다. 각 테마의 3D 주조색을 스캔 팔레트의 기준으로
  다시 잡되, 공통 색상 보정 계층에서 밝기를 안전 대역으로 통일해 QR 대비를 유지합니다.
- **사막과 여우:** 윗면이 좁아지는 사면 타일, 부드러운 외곽 지면 파동, 촘촘한 반구형
  모래 능선을 함께 사용했습니다. 모래 팔레트도 분홍빛에서 황금빛 모래색으로 조정했습니다.
- **장미:** 정원 블록은 기존 연분홍을 유지하고 실제 장미꽃만 진홍·적색 계열로 강조했습니다.
  최종 QR도 분홍 정원 타일과 초록 잎 팔레트에서 파생됩니다.
- **3D↔QR 전환:** 반투명 스캔 카드와 높이가 남은 3D 블록이 동시에 렌더링되던 것이
  두 QR이 겹쳐 보인 원인이었습니다. 카드를 평탄화된 블록 바로 위로 내리고, 블록의
  높이·색상 전환이 끝나는 마지막 구간에 동일한 셀끼리 겹쳐 페이드하도록 수정했습니다.
- **모바일:** 주소 입력 다음에 테마를 먼저 고르고 결과를 확인하도록 DOM 순서를 정리하고,
  테마 카드를 가로 스크롤·스냅 방식으로 압축했습니다. 터치 드래그 판정 거리도 늘려
  시점 회전 중 QR 보기로 잘못 전환되는 동작을 줄였습니다.
- **색상 전환:** 스캔 카드 높이를 평탄화된 블록 바로 위로 내리고 전환 마지막 구간에서
  같은 셀 색끼리 겹쳐 페이드하도록 바꿨습니다. dark 목표 밝기는 `0.18`로 조정해 거의
  검정으로 보이던 테마색을 되살렸으며, 전체 테마의 최소 계산 명암비는 9.8:1 이상입니다.
- **QR 여행:** 결과 창 안에 바로 진입하는 작은 버튼을 추가하고, Space를 두세 번 연속
  입력하면 공중 추진력이 더해지는 다단 점프를 지원합니다. 숲의 발견 지점은 추상 보석
  대신 다람쥐·나비·파랑새·바람꽃·어린나무·버섯 가족으로 교체했습니다.

### 3D ↔ 2D 전환

카메라의 FOV · 고도 · 방위각 · 거리, 블록 높이, 블록 XZ 스케일, 장식 투명도,
색상 평탄화, 구면 곡률, 안개를 **단일 `progress` 값(0~1)** 으로 보간합니다.

- `progress = 0` — 완전한 아이소메트릭 3D 씬 (FOV 42°, 고도 31°)
- `progress = 1` — 완전한 탑다운 스캔 뷰 (FOV 7°, 고도 89.4°)

FOV를 아주 작게 주고 카메라를 멀리 떨어뜨려 **원근 왜곡이 거의 없는 정사영에 가까운
탑다운 뷰**를 만드는 것이 스캔 성공률의 핵심입니다.

### QR 여행 — 1인칭 탐험

**QR 매트릭스가 그대로 지형이 됩니다.** 별도의 충돌 메시 없이 하이트맵 하나로
걷기 · 계단 오르기 · 점프 · 낙하를 처리합니다.

| | |
|---|---|
| 지형 | dark 모듈 = 높은 블록(벽/건물/사구), light 모듈 = 낮은 블록(길) |
| 데스크톱 | WASD/방향키 이동, Space 연속 입력으로 다단 점프, Shift 달리기, 마우스 시점(포인터 락), Esc 종료 |
| 모바일 | 왼쪽 조이스틱 이동, 점프 버튼, 화면 드래그로 시점 |
| 발견 | 테마마다 6곳의 랜드마크. 가까이 가면 짧은 이야기가 뜨고 카운터가 올라감 |

설계에서 실제로 문제가 됐던 것들과 해법:

- **사람이 통로보다 크면 안 된다.** 처음엔 사람 키를 1.6모듈로 잡았더니 통로
  한 칸(1모듈)에 몸이 끼어 화면이 벽 단색으로만 찼습니다. 키 0.9모듈로 줄여
  통로가 골목처럼 읽히게 했습니다.
- **입구가 없으면 못 들어간다.** 아무 데서나 시작하면 눈앞이 벽입니다.
  남쪽 가장자리에서 light 모듈이 가장 깊게 이어지는 열을 찾아 그 앞에 세웁니다.
- **길은 전부 걸어 오를 수 있어야 한다.** 모든 테마의 light 모듈 높이를
  step height(0.58) 아래로 맞춰, 바깥 바닥에서 QR 안으로 그냥 걸어 들어갑니다.
  dark 모듈은 전부 그보다 높아 미로가 됩니다.
- **점프는 두 단계 등반이 되게.** 제자리 점프 높이 ≈ 1.28모듈. 평지에서 벽에
  바로는 못 오르지만, light 블록을 한 번 밟고 뛰면 낮은 벽 위로 올라갑니다.
- **맞붙은 같은 색 블록은 벽이 아니라 벽지처럼 보인다.** 인스턴스마다 밝기를
  조금씩 흔들어(`getColorVariation`) 블록 경계를 드러냅니다.
- **밤 테마는 벽 사이가 캄캄하다.** 탐험 중에만 켜지는 보조 조명을 답니다.
  포인트라이트로 만들었더니 벽에 붙었을 때 거리 감쇠로 화면이 하얗게 타서,
  위치 개념이 없는 앰비언트 필로 바꿨습니다.

### 스캔 카드 — 3D 씬의 색을 그대로 가져간다

탑다운 뷰가 "흔한 검은 QR" 로 바뀌지 않도록, 최종 화면을 **테마 색 모자이크**로
구성합니다. 위에서 내려다본 풍경 안에 QR 판이 놓인 구도입니다.

- 모듈이 **단색이 아닙니다.** 테마마다 6가지 색을 두고 셀마다 골라 칠합니다.
  굵은 노이즈로 색이 뭉치고 일부만 튀게 해서 잎 뭉치처럼 덩어리집니다.
- QR 판 아래에는 살짝 어긋난 **그림자 판**이 깔려 카드가 풍경 위에 얹힌 것처럼 보임
- 판 바깥에는 **테마의 풍경색**과 낮은 소품(풀포기 · 잔별 · 발자국 · 꽃잎)이 그대로 남음
- 3D 블록도 같은 셀별 색으로 수렴하므로 카드가 페이드인될 때 교체가 보이지 않음

#### 색을 살리면서 읽히게 하는 법 — `core/scanColors.js`

색을 그대로 쓰면 QR 이 깨지고, 안전하게만 가면 검은 QR 이 됩니다.
두 요구를 가르는 지점은 **"밝기"와 "색상"을 분리하는 것**입니다.

1. **색상(hue)·채도는 보존, 밝기만 한 값으로 통일한다.**
   선형 RGB 를 곱하는 동안에는 색상과 채도가 정확히 보존됩니다. 그래서 밝기가
   모자라면 먼저 곱해서 올리고, 채널이 1 에 닿아 더 못 올릴 때만 흰색과 섞습니다.
   (처음엔 어두운 색을 곧장 흰색과 섞었더니 채도가 다 빠져 초록이 초록으로
   안 보이는 탁한 색이 됐습니다.)

2. **왜 밝기를 "대역" 이 아니라 "한 값" 으로 맞추나.**
   실제 디코더(ZXing / jsQR)의 바이너라이저는 8×8 픽셀 블록마다 임계값을 정하는데,
   블록 안 max−min 이 **24/255** 를 넘으면 그 블록의 평균을 임계값으로 씁니다.
   붙어 있는 dark 모듈끼리 밝기가 다르면 그 경계 블록에서 밝은 쪽이 light 로
   뒤집혀 코드가 깨집니다. 그래서 팔레트 안 밝기 편차를 7/255 이하로 묶습니다.

3. **디코더마다 그레이스케일 가중치가 다르다.**
   jsQR 은 R·G·B 등가중, ZXing 계열은 `(r + 2g + b) / 4` 로 녹색에 가중을 둡니다.
   같은 색이 한쪽에선 어둡고 다른 쪽에선 밝게 보일 수 있어, **둘 중 더 밝게 보는
   쪽**을 기준으로 맞추고, 두 지표가 크게 벌어지는 색(아주 진한 초록 ↔ 아주 진한
   빨강)은 필요한 만큼만 채도를 낮춥니다.

4. **얼마나 밝게까지 갈 수 있나 — 실측으로 정했습니다.**
   모듈이 아주 클 때(≈48px/모듈) 디코더의 균일 블록 폴백이 "순수 검정이 아닌" 색을
   흰색으로 밀어 버리는 경우가 생기고, 밝을수록 확률이 올라갑니다.

   | 목표 밝기 | 축소 스윕(5 URL × 6테마 × 9단계) | 저장 PNG 1240px |
   |---|---|---|
   | 0.14 | 268/270 (99%) | 36/36 (100%) |
   | 0.18 | 1400px 27/30 (90%) | — |
   | 0.22 | 1400px 26/30 (87%) | 29/36 (81%) |

   `0.14`는 가장 안전하지만 작은 화면에서 거의 검정으로 보여 3D 장면과의 연결감이
   약했습니다. 실측 성공률이 급격히 꺾이기 전인 **0.18**을 선택하고 quiet zone 5.5모듈,
   오류 정정 Q를 함께 적용했습니다. 결과의 계산 명암비는 모든 테마에서 9.8:1 이상입니다.

### 스캔 가능성 보장

그러면서도 스캔 성공률은 여러 겹으로 지킵니다.

1. **명암 대비 10:1 이상 · 팔레트 안 밝기 편차 7/255 이하** — 위 `scanColors.js` 참고.
2. **큰 장식 페이드아웃** — 나무 · 화산 · 우물 같은 큰 오브젝트는 `progress ≈ 0.62` 에서
   완전히 사라집니다. 남는 소품은 **QR 판 정사각 링 바깥**에만 놓입니다.
3. **테마 조명 완전 소등** — 스캔 뷰에서는 테마 조명을 0으로 내립니다.
   (중앙 포인트라이트 같은 국소 밝기 얼룩이 QR 대비를 무너뜨리는 것을 막습니다)
4. **모듈 실루엣 정확히 1×1** — 스캔 카드의 타일이 정확히 한 모듈을 채우므로,
   테마가 블록 지오메트리를 자유롭게 써도 탑다운 결과가 흔들리지 않습니다.
5. **quiet zone 5.5모듈** — 규격 최소치(4)보다 넉넉하게 잡았습니다.
6. **에러 정정 레벨 Q** — 약 25% 복원 여유를 확보합니다.

헤드리스 브라우저로 다음을 검증합니다.

- **8개 테마 × 모바일/데스크톱 뷰포트**의 탑다운 화면을 캡처해 QR 디코더로 되읽기
- **저장되는 PNG 자체**를 디코딩
- 긴 URL(53×53, 버전 9) + UI 테마 전환 후에도 스캔되는지
- URL 5종 × 테마 6종 × 축소 9단계(네이티브 1400px 포함) 디코딩 스윕
- 저장 PNG 를 파일째 디코딩
- **QR 여행**: 테마별로 진입 → 그리드 안까지 걸어 들어가기 → 지형 위 유지 →
  점프/착지 → 랜드마크 발견 → 종료 → 종료 후 스캔 전환까지

### 테마 인터페이스

`src/themes/{themeName}.js` 는 아래 인터페이스를 따르며, 공통 엔진 위에
플러그인처럼 갈아끼울 수 있습니다.

```js
getBlockGeometry(isDark)  // → { geometry, material, height }  블록 지오메트리/재질
getPalette()              // → { dark, light, ground, sky, scanDark, scanLight, ... }
placeDecorations(size)    // → [{ type, position, rotation, scale }]  배치 좌표 배열
getBackgroundSetup()      // → { background, fog, lights, objects }
```

선택 확장:

```js
getCurvature()            // → 구면 배치 강도 (0 = 평면)
getHeightJitter()         // → 셀별 높이 흔들기 (사구 능선, 도시 스카이라인)
getCellScale({col,row,isDark,matrix,size,defaultScale})
                          // → 셀 하나의 높이 배율을 테마가 직접 설계 (계단·단)
getColorVariation()       // → 인스턴스별 밝기 변주 (1인칭에서 블록 경계가 보이도록)
getBlockSpread()          // → 3D 뷰의 블록 XZ 스케일 (1에 가까울수록 덩어리)
getPlayerLight()          // → 탐험 중 보조 조명 세기
getScanColors()           // → 탑다운 모듈 색 후보 { dark: [...], light: [...] }
placeLandmarks(size, m)   // → 탐험 중 발견하는 지점 배열
buildDecoration(spec)     // → THREE.Object3D  (배치 스펙 → 실제 오브젝트)
update(dt, ctx)           // → 프레임마다 호출 (도시의 자동차, 연못 물결)
```

`pickWalkableCells` 는 light 모듈인지만 보고 **연결성은 보장하지 않습니다.**
사방이 막힌 골목 주머니가 뽑히면 그 자리의 랜드마크는 영영 발견할 수 없습니다.
대신 `_shared.js` 의 **`pickConnectedCells(size, matrix, count, seed, options)`** 를
쓰면 바깥 테두리에서 BFS 로 실제 도달 가능한 칸만 고릅니다. `options.minDegree` 를
주면 길이 그만큼 갈라지는 **교차로**만 고를 수 있어(모름표 탐험대의 몰라 정류장처럼)
"여러 길이 만나는 곳" 을 우연이 아니라 계산으로 보장할 수 있습니다.
`collectConnectedCells()` 는 각 칸의 차수까지 담아 그대로 돌려줍니다.

`placeDecorations` 는 두 번째 인자로 매트릭스를 받습니다.
스펙에 `persistent: true` 를 주면 탑다운 스캔 뷰에서도 남고(반드시 QR 판 바깥),
`snapToGround: true` 를 주면 그 자리의 블록 높이 위에 얹힙니다(둔덕 위의 나무).

블록 지오메트리는 엔진이 **밑면 1×1, 높이 1, 원점은 밑면 중앙**으로 정규화하므로
테마는 크기를 신경 쓰지 않고 형태만 정의하면 됩니다.

### 지형에 계단 만들기 — `getCellScale`

`getHeightJitter()` 는 엔진 안의 노이즈로 셀 높이를 흔들기 때문에 **어느 칸이 낮은지를
테마가 정할 수 없습니다.** 그래서 길과 벽 사이가 비어 버리고, 걸어서 올라가는 지형을
만들 수 없었습니다.

`getCellScale()` 을 구현하면 셀 하나하나의 높이 배율을 테마가 직접 정할 수 있습니다.
이 값 하나가 **렌더 높이와 충돌 높이를 함께** 결정하므로, 보이는 계단이 곧 실제로
밟히는 계단이 됩니다. 구현하지 않은 테마는 기존 지터 동작 그대로입니다.

Explorer 의 `stepHeight` 는 0.58 이므로 한 단을 그보다 낮게 잡으면 **점프 없이 걸어서**
올라갑니다. 모름표 탐험대는 이렇게 높이 사다리를 설계했습니다.

| | 높이 | 이전 단과의 차 |
|---|---|---|
| 탐험길 | 0.40 | — |
| 1단 | 0.92 | +0.52 · 걸어서 |
| 2단 | 1.44 | +0.52 · 걸어서 |
| 3단 | 1.96 | +0.52 · 걸어서 |
| 벽 | 2.60~3.00 | +0.64 이상 · 점프 필요 |

실측한 점프 도달력은 단발 +1.80 / 삼단 +3.52 입니다. 그래서 계단은 걸어 올라가고,
계단 꼭대기에서 한 번 뛰면 능선(벽 위)에 올라 세계 전체를 내려다볼 수 있습니다.
능선끼리의 높이차는 0.58 이내라 일단 올라서면 걸어 다닐 수 있습니다.

## 이미지 저장

`이미지 저장` 버튼은 현재 테마의 탑다운 스캔 뷰를 1240×1240 정사각형 PNG로 다시
렌더링해 내려받습니다. 화면 상태와 무관하게 항상 정면 탑다운으로 담기므로,
3D 장면을 보고 있는 중에 눌러도 스캔되는 이미지가 나옵니다.

## 접근성

- 장식용 아이콘에 `aria-hidden` — 스크린리더가 `qr_code_scanner` 같은 ligature 이름을
  읽지 않습니다.
- 테마 선택은 roving tabindex 라디오 그룹 — 탭 정지점은 하나, 방향키로 이동합니다.
- 3D 캔버스는 `tabindex`·`role="button"` 이며 Enter/Space 로 뷰를 전환할 수 있고,
  포커스 링이 보입니다.
- `prefers-reduced-motion: reduce` 이면 3D↔2D 전환을 애니메이션 없이 즉시 끝냅니다.
- QR 여행의 발견 알림과 카운터는 `aria-live` 로 읽힙니다.

## 공유 링크

현재 URL과 선택한 테마는 쿼리 파라미터로 인코딩됩니다.

```
https://<host>/?url=<encodeURIComponent(URL)>&theme=b612
```

공유받은 사람이 이 링크로 접속하면 동일한 씬이 그대로 재생성됩니다.
테마를 바꾸거나 새로 생성할 때마다 주소창도 같은 형식으로 갱신됩니다.

## 배포

**https://qr612.chichiboo.link** — GitHub Actions 로 GitHub Pages 에 자동 배포됩니다.

기본 브랜치에 push 되면 `.github/workflows/deploy.yml` 이 돌면서
`npm ci` → `npm run build` → `dist/` 를 Pages 아티팩트로 업로드하고 배포합니다.
Actions 탭에서 `workflow_dispatch` 로 수동 실행할 수도 있습니다.

커스텀 도메인은 `public/CNAME` 에 담겨 있어 빌드할 때마다 `dist/CNAME` 으로 복사됩니다.
워크플로에 이 파일의 존재를 확인하는 단계를 넣어두었으므로, 실수로 지워지면 배포가
성공한 뒤 도메인이 풀리는 대신 빌드 단계에서 바로 실패합니다.

DNS 는 `qr612` 서브도메인에 CNAME 레코드로 `chichiboo123.github.io` 를 가리키면 됩니다.
저장소 Settings → Pages 에서 **Enforce HTTPS** 를 켜두는 것을 권장합니다.

정적 사이트이므로 다른 호스팅(Cloudflare Pages, Netlify 등)에 올릴 수도 있습니다.
빌드 명령 `npm run build`, 출력 디렉터리 `dist`, Node 18 이상이면 되고,
`vite.config.js` 의 `base: './'` 덕분에 서브 경로 배포에서도 동작합니다.
